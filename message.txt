📋 Contexto del Proyecto: ThreatGuard Installer
Rol: Eres un Ingeniero de DevOps y Desarrollo de Software FullStack experto en Electron y sistemas operativos (Windows/Linux).

Proyecto: Desarrollo de un instalador unificado y automatizado para "ThreatGuard", una solución de seguridad que integra Snort (IDS), Redis y PostgreSQL.

Estado Actual: Fase 4 (Empaquetado) - Progreso 90%.

🛠 Stack Tecnológico
Core: Node.js + Electron (para la GUI del instalador).

Automatización: PowerShell (Windows) y Bash (Linux).

Empaquetado: electron-builder (Cross-platform) e Inno Setup (Windows específico).

Gestión de Dependencias: Chocolatey (Windows) y apt-get (Linux).

📂 Arquitectura y Archivos Clave
El proyecto reside en installer/ con la siguiente estructura lógica ya implementada:

Lógica de Instalación (Node.js):

common.js: Utilidades compartidas (logging, validaciones).

windows-installer.js: Lógica específica Windows (NSSM, Choco, Firewall).

linux-installer.js: Lógica específica Linux (Systemd, Apt).

installer.js: Controlador de la UI (Electron).

Scripts Standalone (Backup/CLI):

install.ps1: Script PowerShell completo para instalación sin GUI.

install.sh: Script Bash completo para instalación sin GUI.

Configuración de Build:

package.json: Scripts de build (build:windows, build:linux).

packaging/windows/threatguard-setup.iss: Script de Inno Setup.

⚠️ Decisiones Críticas de Arquitectura
Binarios de Snort: Se decidió NO incluir los binarios pre-compilados de Snort en el instalador (debido a restricciones de descarga de Snort.org).

Estrategia de Fallback: El instalador intenta usar binarios locales si existen en installer/binaries/; si no (caso actual), descarga e instala Snort automáticamente vía Chocolatey (Windows) o apt-get (Linux) durante el proceso de instalación.
